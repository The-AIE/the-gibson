## Convergent advisory findings

1. **Narrow the promise.** A description is incomplete input, and an evidence bundle cannot certify arbitrary enterprise reliability. Define the product/risk profile and explicit unknowns.
2. **Traceability alone is insufficient differentiation.** Existing specification tools and Atomic overlap the proposed artifact chain. Test owner understanding and trustworthy outcomes, not document generation.
3. **Start with portable artifacts and a useful slice.** All four favor versioned readable contracts and benefit before broad hosted/orchestration infrastructure.
4. **Separate integrated experience from codebase/deployment consolidation.** They recommend shared contracts and optional presentation first; source audit confirms an existing Gibson/Agent Kontrol boundary to reuse.
5. **Guard against false assurance.** A primary model's own tests, a checked box or an attestation cannot establish full product correctness. Preserve independent evidence and authority.
6. **Use comparative/held-out evaluation.** Include requirement changes, negative/abuse cases, user comprehension, total effort and a simpler baseline.
7. **Integrate selectively.** Langfuse is measurement, Atomic is an optional compatibility/provenance comparison, and durable workflow/execution platforms must earn their cost.

Agreement is a source of hypotheses, not proof those hypotheses are correct.

## Recommendations not adopted as policy

**GLM's initial deterministic-checks-only authority.** The first memo proposes treating model review as non-authoritative and deterministic checks as sole verification authority. That conflicts with current independent-review requirements and also does not resolve model-authored test inadequacy. This research does not adopt it; GLM explicitly retracts it in the source-informed delta. Reproducible checks and accountable independent review establish different properties.

**Blanket human release approval or generic waiver paths.** Grok/Claude discuss human technical sign-off or owner risk acceptance. Some product profiles/actions legitimately require specialists or owner authority, but this does not create a new owner merge gate for every Tier C change or permit waiving protected checks. Preserve the existing closed gates and exact-head floors.

**All truth must live in Git.** The panel commonly favors a rebuildable control-plane cache. For accepted specifications/source-linked decisions, portable versioned artifacts are attractive. However, Agent Kontrol already has legitimate runtime/task/attempt state and transactional needs. Choose canonical homes per fact and an export/recovery contract; do not migrate all runtime truth into Git merely to satisfy a slogan.

**Universal implementer prohibition on tests/spec edits.** Claude's table is a useful trust-boundary provocation, not an adopted workflow. Builders must be able to add regressions; material business changes need the appropriate acceptance, and test/spec changes need applicable independent review. The generator's self-report is insufficient, but freezing every artifact forever would create unnecessary friction.

**Arbitrary numeric stopping rules.** GLM suggests an owner-edit percentage and a wall-time multiplier. Those are unvalidated proposal examples, not accepted thresholds. A well-understood correct draft may need few edits; low edits alone do not prove rubber stamping. Use seeded errors, comprehension/calibration and predeclared trial margins.

**Enterprise assurance as a late phase.** Some memo increment tables defer enterprise profiles. Our plan captures applicable obligations at the first specification and requires the actual release's floor before making its readiness claim. No later checklist retroactively makes an earlier release enterprise-ready.

## Integrated-product conclusion to test

The current recommendation remains one coherent owner journey, portable Gibson contracts/evidence and Agent Kontrol coordination/presentation with explicit authority. Test a static/GitHub-native view and an acceptance/evidence-compiler wedge first. A literal repository merger is a later independent decision.

External models did not inspect Agent Kontrol's actual implementation. Its documented existing boundary was supplied in round two; the source audit remains the provenance for that fact, not model code inspection.

## Product plan changes after the panel

- Keep description/spec/scoped-increment/real-release benefits, but test whether a thin evidence-and-change layer over existing spec tools is enough.
- Add a static-report/PR-inbox baseline before a new persistent workbench.
- Explicitly test owner calibration and false assurance, including plausible but incorrect specifications/evidence summaries.
- Include changed requirements and stale evidence from the first demonstrator.
- Prefer a bounded synthetic request/export workflow over money/payment features that add unrelated risk to the first proof.
- Record enterprise responsibilities, privacy/telemetry and operating/exit cost before adapter adoption.
- Keep future implementation/authority decisions separate from this research package.

## What is still unproven

Customer demand, willingness to adopt/pay, comparative spec fidelity, usable incremental scope, actual running integrated UX, portability across multiple execution adapters, repeated verified delivery and the value/cost of Atomic or Langfuse. The panel supplies no production trial results, certification, benchmark reproduction or release approval.
