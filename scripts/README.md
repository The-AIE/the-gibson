# scripts/ — deterministic harness tooling

No-model by design ([docs/15](../docs/15-model-economics.md): "no-model checks stay
no-model"). POSIX bash + plain Node. **No package dependencies.** Every script
prints Ask-Contract style help via `--help` (what / why / risks / examples).

## Inventory

| Script | Contract |
|---|---|
| [`claim.sh`](claim.sh) `<issue> <slug> <scope…> [--slice]` | Atomic claim: `agent-claimed` label → refuse a second claim on the same issue (`--slice` for a deliberate lane) → verify no scope overlap against the **one authoritative live-claim view** — live PR-body claims (`pr-claims.sh`) plus legacy ledger rows, read from `origin/main`/GitHub (#153) → empty-commit + push a branch → open a **draft PR whose body carries the claim** (`- Active-work claim: <id>`) → create worktree `../wt-<issue>-<slug>` + branch. No file anyone edits, so concurrent lanes never conflict on a shared path. **`node` is required before any mutation:** `scope-overlap.mjs` is the only implementation of the overlap/admission decision and there is no weaker fallback — a host without node refuses the claim outright rather than labelling, branching and opening a PR on a check it could not run. Every claim-path read (live inventory, ledger tree, legacy table) fails closed: unreadable or malformed is never recorded as "no live claims", and those refusals happen before the first mutation. **Admission after publication:** a pre-create read cannot be atomic, so the claim is re-decided once its PR exists via `scope-overlap.mjs --admit-pr`. Because GitHub's PR listing is eventually consistent, seeing your own claim does not prove you can see a rival's — admission waits for a **quiescent inventory** (identical claim-relevant rows on `GIBSON_CLAIM_ADMIT_STABLE_READS` consecutive reads, default 2, spaced by `GIBSON_CLAIM_ADMIT_DELAY`, giving up after `GIBSON_CLAIM_ADMIT_ATTEMPTS`). The sensor takes those reads **itself**; nothing hands it an inventory, because an option to supply one is a forged-evidence path (a fabricated empty or self-only inventory would buy a green admission over a live conflicting claim). The barrier has a production **floor** of 2 matching reads spaced ≥1s and documented **maxima** (60 attempts / 30 stable reads / 60s delay, so a claim attempt stays operationally bounded): `GIBSON_CLAIM_ADMIT_*` may only raise the floor, and a below-floor, above-maximum, or non-finite-safe-integer value (a 400-digit literal, anything past `Number.MAX_SAFE_INTEGER`) is a usage error, not a silent clamp — there is no supported switch that turns it off and no `*_TEST_*` variable production reads. The spacing between reads is an **internal timer**, not a `PATH`-resolved `sleep` command, so nothing in the environment can shorten or skip it. An inventory that never settles refuses and rolls back. Scope overlap *and* same-issue exclusivity are both decided there, on the lower-PR-number tie-break, so two lanes on one issue with disjoint scopes can no longer both survive without `--slice`. That tie-break gives a deterministic winner **when each lane's PR becomes visible to the other inside its quiescence window** — a bounded guarantee, not an unconditional one. **Rollback does the claim first, artifacts second:** nothing is destroyed until this lane's own PR is positively bound (exact claim id *and* head branch), positively closed, and freshly proven no longer live. A failed close, a close that reported success while the claim is still listed, an unreadable/malformed/ambiguous inventory, a `gh pr create` that succeeded with unparseable output, **and a `gh pr create` that exited non-zero** all retain **every** artifact — worktree, both branches, and the issue-wide label — name the uncertainty, and exit `INCOMPLETE`/non-zero. That last case is not defensiveness: a non-zero exit is the *client's* view of the call, and GitHub can create the PR and then lose the response, while the eventually consistent PR list stays empty for a while afterward. Destroying a branch on that evidence destroys the work behind an open claim, so from the instant `pr create` is invoked nothing is removed until this lane's PR is bound and proven closed. Only then do the shared [`lib/claim-guards.sh`](lib/claim-guards.sh) protections run — registered-worktree resolution, exact path/branch/OID proof, dirty refusal, compare-and-swap local and remote branch deletion — and anything they cannot prove is kept and named too. `agent-claimed` is issue-wide: it is removed only after a fresh authoritative sibling inventory and a fresh label read agree it is safe. **A killed lane is different from a refused one:** rollback runs from an EXIT trap, so SIGKILL/power loss/termination before it finishes can leave an open draft PR (a live claim), the label, a branch and a worktree — clear those with [`claim-reaper.sh`](claim-reaper.sh) or the manual recovery in [docs/troubleshooting/claim-conflicts.md](../docs/troubleshooting/claim-conflicts.md). |
| [`lib/claim-guards.sh`](lib/claim-guards.sh) | Sourceable, read-only cleanup guards shared by `claim.sh`'s admission rollback and `release-claim.sh`'s terminal cleanup — the second `.sh` in `scripts/` that is `source`d rather than run, so it carries the same Ask-Contract `--help` and a direct run is a loud usage error (exit 2). Answers the three questions that gate a destructive step: which **registered** worktree is really on a branch (enumerated from `git worktree list --porcelain`, never guessed from a path convention), where a path physically lives once symlinks resolve, and whether the remote branch exists at exactly which OID. Every answer distinguishes *unreadable* from *absent* — `git ls-remote --exit-code` conflates them, and that conflation is how "the query failed" became "the branch is gone". It exists because both paths delete worktrees and branches: while each carried its own copy of these checks, a protection added to one silently did not exist in the other. |
| [`pr-claims.sh`](pr-claims.sh) `list\|list-open-numbers\|find\|find-terminal\|find-terminal-pr\|close <owner/repo> …` | Reads GitHub-native PR-body claims. `list`/`find` cover live **open** claims (TSV: number, claim id, scope, head branch, URL, created, updated, is_cross_repository — eight fields; `is_cross_repository` is eighth after `updated_at`/`updated`). `find-terminal <repo> <claim-id>` (#153) searches every PR state and returns only claims whose PR has reached MERGED or CLOSED, with columns for issue, exact head SHA, state, is-cross-repository, merge-commit SHA (empty when CLOSED unmerged), and base repository — re-derived from the PR's own URL, never assumed from the query argument — used by `release-claim.sh` to prove exact identity and worktree/branch safety before releasing a claim after its PR is done, when no ledger row exists. `find-terminal` is **candidate-first**: it selects only PRs whose body carries the requested claim id exactly, then validates those in full. `list` is an inventory and still validates every claimed open PR, so a malformed *live* claim correctly poisons it; `find-terminal` is a lookup, so an unrelated historical PR whose body predates the marker format cannot permanently block every future release. Matching malformed/duplicate markers, two PRs carrying the same exact claim id, and any gh/jq/pagination failure still fail closed. `find-terminal` also accepts a strict **legacy terminal-claim schema** for claims merged before the machine markers existed (the motivating case is `mrhinkle/the-gibson#143`): only when **both** `- Claim scope:` and `- Issue: #` are entirely absent, it parses the issue from exactly one `Closes #<n>.` line and the scope from exactly one `## Cumulative scope` section of backticked path bullets. Nothing is invented — a marker-only body, prose, a bare bullet, an empty/duplicated section, an unsafe/absolute/`..`/repeated path, or a *current*-format body missing one required field all still refuse. `list` never accepts the legacy schema; open claims must carry today's markers. `find-terminal-pr <repo> <claim-id> <number>` answers the **bound** question — "is PR #number terminal evidence for exactly this claim id?" — with every check unchanged. It exists because a released claim id is free to be reused, which makes the id-only lookup permanently ambiguous from the second generation on, while the caller that already knows its PR has no ambiguity at all. `list` is buffered, never streamed: `--paginate` emits page 1 before it can discover that page 2 failed, so a partial inventory is never handed to a caller. `list-open-numbers <repo>` answers a deliberately **different**, body-agnostic question — every open PR number, regardless of what its body says. `list` only sees a PR while it carries a well-formed claim marker, so "the claim id is absent from `list`" is satisfied both by a PR that closed and by a PR that is still wide open with its marker deleted or rewritten; `list-open-numbers` is how `release-claim.sh` tells those apart before reporting a claim released. Same pagination and fail-closed contract, and a non-numeric row poisons the whole command. |
| [`claims-status.sh`](claims-status.sh) `[--issue n] [--markdown] [--ref ref]` | The live claim table, rendered from live PR-body claims **and** legacy `docs/claims/*.md` / `docs/active-work.md` rows together. Flags claims older than 24h as STALE. Default (no `--ref`): successfully fetch `origin` main/master and read that exact remote-tracking ref — a failed fetch or missing remote-tracking ref exits **1** and never falls back to local main/master or prints `no live claims` on an unread base. Explicit `--ref` is operator-selected and is used as given. A failed `pr-claims.sh list` (auth, pagination, malformed evidence, missing reader) also exits **1** with a diagnostic — never a suppressed failure printed as absence. |
| [`release-claim.sh`](release-claim.sh) `<issue> [--claim-id id] [--pr n] [--prefix ns] [--repo owner/name]` | Post-merge cleanup, representation-agnostic. The live open-PR claim inventory (`pr-claims.sh list`) is read **authoritatively, not best-effort**: a missing/unexecutable reader, an API or pagination failure, or a malformed row refuses before any PR, label, worktree, branch, or ledger mutation — an unreadable claim view is never an empty one (#153). A live open PR-body claim is released by closing that PR and then handing straight to the same verified terminal cleanup below (never a guessed worktree path, never a force-remove, never a `\|\| true` branch delete). `gh pr close` is the first irreversible mutation, so every identity check that authorizes it runs **before** it — including that the PR's head branch is exactly the branch its claim id derives from; an exact claim marker in the body of a PR on an unrelated branch is not authority to close that PR, and the mismatch exits **1** with nothing mutated (including under `--dry-run`). Where the handover cannot be made safely — the just-closed PR's own terminal evidence unreadable, ambiguous, contradicting its state, **or simply absent** — it is close-only and returns **3** with the leftovers named, `agent-claimed` preserved, and a `RECOVERY:` line naming the bound re-run (`--pr <n>`), never a success message and never a mid-mutation `exit 1`. An absent terminal row after a close is not evidence that there is nothing left; it is evidence the run cannot see the PR it just closed, so the close-only path never removes `agent-claimed`. The post-close proof also binds the **PR number**, not just the claim id: the claim inventory drops a PR whose marker was removed or rewritten while it stays wide open, so `list-open-numbers` is cross-checked and a still-open number (or an unreadable answer) refuses success and exits 3. The same evidence failure *before* any mutation stays a plain refusal (exit **1**, nothing done) that names which binding failed: 1 = refused, 3 = did part of the work. A live legacy ledger row is released by removing it (signed commit from a throwaway main worktree, so the canonical checkout never moves); a claim whose PR already **merged or closed** and never had a ledger row is released via a dedicated, self-contained path (#153) that verifies the exact issue/claim-id/PR-number/head-branch/head-SHA/base-repository/cross-repository=false/terminal-state directly against that finished PR, then proves the exact registered worktree is on that branch, clean, and at that head SHA (or safely contained in the merge) *before* touching it — never `rm -rf` of an unregistered/default-path directory, never a force-remove of a dirty worktree — and rereads GitHub **fail-closed** afterward before deciding the label. No ledger row is ever invented. Either way: remove worktree, delete branch, remove label and **verify** it is gone. `--claim-id` releases one slice of a multi-slice issue and keeps the label while any sibling (ledger **or** PR-body) remains. Exit 3 = ran but did not finish (claim or label still live); never printed alongside a success message. **Repository binding:** before any PR-evidence-driven cleanup it proves that `GIBSON_CANONICAL`'s own normalized origin repository (https, ssh, scp-like, port, `.git`, case-insensitive) IS the repository the evidence came from — a fork or second clone carrying the same branch and the same commits is not identity. Repository identity itself is resolved once from `--repo`, then `gh repo view`, then the origin remote; if none can answer, the run stops **before** any mutation instead of silently skipping the authoritative inventory. The post-mutation sibling reread is fail-closed too: an unreadable or malformed inventory, or a surviving sibling whose `agent-claimed` label is missing/unreadable, preserves the label and returns 3. `--pr <n>` binds a terminal release to one exact PR, which is how a legitimately reused claim id is released without weakening the ambiguity refusal. |

## How to use (quick path)

```bash
GIBSON=~/Code/the-gibson
cd ~/Code/acme-app

# Claim + worktree
$GIBSON/scripts/claim.sh 42 password-reset 'app/api/auth/**'

cd ../wt-42-password-reset
$GIBSON/scripts/gate-baseline.sh
# ... implement ...
$GIBSON/scripts/gate.sh && git commit -s -m "feat(#42): reset tokens"

# Intentional suite reduction (journaled; not a side effect of re-baseline):
$GIBSON/scripts/gate-baseline.sh --regenerate --reason "removed obsolete flaky suite after #42"
# And put a matching visible waiver on the PR:
#   Test-integrity: removed N for <reason>

# After merge
cd ~/Code/acme-app
$GIBSON/scripts/release-claim.sh 42

# Solo grind
$GIBSON/scripts/loop.sh --runner grok --repo ~/Code/acme-app

# Multi-lane fleet (profile is local — see templates/fleet/)
export FLEET_PROFILE=/absolute/path/to/local.profile
$GIBSON/scripts/loop-fleet.sh --status
$GIBSON/scripts/loop-fleet.sh --start
$GIBSON/scripts/loop-fleet.sh --halt

# Preview for UX eval
export BASE_URL="$($GIBSON/scripts/preview-url.sh 123)"
```

## Gate command configuration

Resolution order per step (`generate` / `typecheck` / `lint` / `test` / `build`):

1. Env: `GIBSON_TYPECHECK`, etc.
2. `.agents/gate.json` in the target repo (legacy fallback: `.gibson-gate.json`)
3. Commands recorded in `.gibson-baseline.json`
4. `package.json` scripts (`typecheck`, `lint`, `test`, `build`)
5. Defaults (`npx tsc --noEmit`, `npm run lint`, …)

Example `.agents/gate.json` — vendor-neutral on purpose, so a target repo can be
driven by any harness (docs/13):

```json
{
  "generate": "npx prisma generate",
  "typecheck": "npx tsc --noEmit",
  "lint": "npm run lint",
  "test": "npx vitest run",
  "build": "npm run build"
}
```

## Test-integrity summary contract (issue #70)

Prefer an explicit machine line from the test suite (works with any runner):

```
GIBSON_TEST_METRICS total=42 skipped=2 todo=0
```

Also parsed: Vitest / Jest / node:test / TAP summary shapes. Unparseable,
negative, or non-integer metrics **fail closed** (never become zero). Known
limit: count-only comparison cannot detect equal-count swap of one test for
another — see [docs/06](../docs/06-quality-gates.md).

Local `gate.sh` uses `.gibson-baseline.json` (gitignored). A PR-local baseline
never authorizes a remote merge: `ci/gibson-gate.yml` ships the protected
four-job template that re-derives metrics at the merge-base with the immutable
base-owned helper and compares via `--trusted-source merge-base:<sha>`. The
template is **inert until an owner activates** the unique required check
`test-integrity` under issue #68 — installing the file alone is not protection.

## Design notes

- **claim commits on main** are the intentional exception to worktree isolation
  ([docs/05](../docs/05-concurrency.md)) — claims must be visible instantly.
- **upstream-sync** never touches `local/` (covenant in [docs/18](../docs/18-fork-and-upstream.md)).
- Prefer fixing the harness over adding script flags for one-off exceptions.
